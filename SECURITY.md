# Security model

The Quattro plugin runs inside the shared, long-lived `omarchy-shell` process. Its QML therefore admits only the shaped output of `scripts/status.sh`: one of `missing`, `error`, or `installed<TAB><version>`. The helper caps raw `pacman` output at 96 bytes before parsing, caps the version field at 64 ASCII characters, and never returns partial package data. GNU `timeout` owns the package-query process group, sends TERM after three seconds, and sends KILL one second later. If the status controller itself is killed, that independent timeout process retains the same finite lifetime for the query and its descendants. The helper creates no temporary files.

Install, update, launch, and removal are detached from `omarchy-shell` immediately. Omarchy's session manager owns the launched application or visible terminal. The plugin has no background service, watcher, network process, open file, or privileged QML process.

The visible install and update terminals are user-bound tasks: metadata and checksum requests have short fixed deadlines, and the package download has a 30-minute curl request ceiling and 2 GiB byte ceiling inside a 1,810-second outer deadline with a further five-second KILL grace. Private temporary files are removed on normal or trappable helper exit; an uncatchable SIGKILL can leave only that private temporary directory for the operating system's temporary-file cleanup. After visible `sudo` authentication, a fixed root-side script uses a 120-second bounded, nonblocking, no-final-symlink copy into a fresh mode-0700 root-owned directory under `/var/tmp`, rejects a copy one byte over the advertised limit, requires a root-owned single-link regular mode-0600 file, and repeats SHA-256 verification before invoking the fixed `/usr/bin/pacman` path on that staged copy. The `pacman` transaction intentionally has no fixed wall-clock deadline because it waits visibly for the local package manager; the user may close the terminal, and Omarchy's terminal/session manager owns and reaps that process tree. The final `omarchy-pkg-drop` transaction in removal has the same visible user-bound lifetime after all bounded shutdown and trust-cleanup checks pass. A terminal completes normally when its helper exits and waits only for the presentation acknowledgement; plugin reload does not adopt or hide an already launched terminal.

The launched Studio application is likewise an intentional session-bound task with no fixed wall-clock ceiling. `uwsm-app` transfers it to the graphical session manager, which owns its Electron children and reaps the application after normal Quit or session teardown. Studio's own daemon and local-site processes may remain active for as long as the user keeps sites running, including after choosing Studio's explicit “Keep site running” quit option. Studio's visible stop/delete controls or bundled CLI normally end those tasks; the Quattro remover supplies the independently bounded TERM-to-KILL scope described below before it permits package removal. Disabling, reloading, or removing the lightweight Quattro shell integration does not silently terminate a launched Studio application or destroy site data.

The removal terminal refuses to proceed while a Studio main-process PID owns a mapped Hyprland window. Studio's native **Keep site running** quit action closes that window while intentionally retaining the main Electron process to supervise the site. The remover accepts that state only when a bounded Hyprland query returns a schema-valid client array and none of the exact current-user Studio main PIDs owns a mapped client; missing session identity, timeout, malformed compositor data, or any query error fails closed. After that verified normal quit, it runs the fixed bundled `site stop --all --avoid-telemetry` command inside a uniquely named transient systemd user scope. A private nonce gate keeps the command closed until the remover verifies the scope ID, active state, current-user ownership, exact control group, finite runtime and stop timeouts, `KillMode=control-group`, `SendSIGKILL=yes`, a new session/process-group leader, and nonce-bearing command line. systemd argument expansion is disabled so the fixed Bash supervisor reaches Bash verbatim. Only the verified cgroup is signalled; the remover does not signal saved process groups or unrelated same-user processes.

The inner Studio CLI receives TERM after 60 seconds and KILL five seconds later. The transient scope has a 70-second runtime ceiling, a five-second stop ceiling, and forced final KILL for every descendant, including the scoped CLI worker and its children. The direct `systemd-run` controller is capped at 80 seconds plus a two-second KILL grace. User-manager probes and actions receive a three-second deadline and one-second KILL grace. Containment verification uses a ten-second loop deadline, and cooperative cancellation uses a five-second TERM loop followed by a seven-second KILL-poll loop; each loop can finish one already-started, bounded user-manager call after its deadline. The direct controller receives a separate one-second TERM grace before KILL and is reaped. After the CLI reports that all sites stopped, the remover again fails closed if any Studio main PID owns a mapped window. It then sends TERM with a five-second grace, followed when necessary by KILL with a five-second grace, only to exact current-user PIDs whose first command-line argument is rooted under `/usr/lib/studio/`; every PID is revalidated immediately before signalling. Failed verification, nonzero shutdown, a surviving Studio process, or a browser-trust cleanup error aborts before the package transaction. A package-manager error fails the visible removal transaction itself. The transient scope may briefly outlive a forcibly killed removal terminal, but its independent 75-second ceiling remains authoritative and the package transaction cannot run after that controller dies.

The installer caps the GitHub release response at 256 KiB before `jq` parses it and rejects more than 64 assets. It accepts only an `omarchy-v<semver>` tag and a fixed package filename shape. Download URLs are constructed from the fixed RegionallyFamous repository rather than accepted from the response. The checksum file is capped at 512 bytes and must name the selected package exactly. Package downloads are capped at 2 GiB. Every request is HTTPS-only and has both connection and wall-clock deadlines.

Production downloads use a fresh private temporary directory. The test-only explicit download path must be an absolute, writable directory and cannot be a symlink or special file. Existing partial files are rejected before curl can open them.

Linux certificate trust never passes Studio's mutable user-owned CA pathname to an elevated process. Studio opens the certificate without following its final symlink, requires one bounded regular PEM file, detects size and metadata changes during the read, and validates a self-signed WordPress Studio CA before authorization. The privileged command receives only an embedded exact-byte snapshot and its file and DER fingerprints. Install, rollback, and package removal share a fixed root-side lock; installation stages under the fixed root trust directory, verifies before and after atomic replacement, re-verifies after trust extraction and bundle verification, and restores the previous anchor only when the destination still contains that transaction's exact certificate. Failure paths refresh the bundle against the resulting anchor state and remove transient transaction files; if restoring an earlier anchor fails, its root-owned backup is preserved for recovery. Package removal refreshes trust even when the anchor is already absent, so a failed refresh remains retryable. Chromium and Firefox NSS imports read only the installed root-owned anchor.

Linux hosts updates likewise never pass a mutable user temporary file to elevation. Studio embeds a maximum-64-KiB payload and the pre-authorization `/etc/hosts` fingerprint in a literal command, serializes writers with a fixed root-side lock, uses a random noclobber stage beside `/etc/hosts`, verifies the current file before writing and immediately before atomic replacement, preserves and rechecks its attributes and bytes, verifies the committed destination, and syncs the containing directory. Concurrent legitimate edits fail closed. Custom-domain HTTP and HTTPS listeners bind explicitly to `127.0.0.1` and `::1`; Playground/Sandbox WordPress, native PHP proxy and probe, and PHP error-recovery diagnostic listeners are confined to `127.0.0.1`.

Quattro package installation and removal happen in Omarchy's visible terminal; plugin-free Arch operations happen in the user's invoking terminal. `sudo` is never started by QML and never receives a password programmatically. It is used for the local `pacman` transaction. The package installs its Chromium sandbox helper at `/usr/lib/studio/chrome-sandbox` as a root-owned setuid file with mode `4755`; the installer always restores that fixed mode after installation and conditionally repairs broader read and execute permissions when required. Studio otherwise runs as the desktop user. Separately, the package attempts to grant only `cap_net_bind_service` to Studio's bundled Node runtime so local sites can use ports 80 and 443; a failure prints a visible package warning and leaves privileged-port/custom-domain behavior unavailable without granting that capability to Electron or the Studio process broadly.

The Quattro removal action performs current-user browser trust cleanup before package removal so the required packaged libraries remain available and an incomplete cleanup leaves the package installed. It considers fixed Chromium NSS locations and at most 24 existing Firefox default-profile databases under the current user's home, rejects unsafe ownership, symlinks, and special files, and removes only the `WordPress Studio CA` entry whose SHA-256 fingerprint matches Studio's retained user CA. Every certificate inspection and deletion has an outer TERM-to-KILL deadline. A mismatch is preserved, unrelated certificates and Studio data are never deleted, and any incomplete cleanup is reported as an error.

Native package revision 3 and later also installs that cleanup as `studio-omarchy-cleanup-user-trust` so plugin-free installations have the same complete removal path. It must run as the desktop user before the package is dropped; it never changes system files or invokes elevation.

Automated regressions cover the exact and one-over byte ceilings, the exact and one-over asset count, multibyte status input, malformed metadata, failed child processes, controller TERM and SIGKILL containment both before the bounded status query begins and after its package process starts, checksum mismatch and malformed checksum structure, pre-authorization and post-authorization symlink, FIFO, oversized, and same-inode package mutation attacks, certificate substitution and mutation, hosts-file substitution and concurrent edits, loopback-only listeners, and the absence of partial data returned to QML.
